# Development Diary - August 2026

---

## 2026-08-28: Android gamepad input and touch-editor fixes

Added native SDL3 gamepad controls for the Android port: right-stick cursor,
left-stick camera movement, face-button clicks/actions, D-pad keyboard input,
and shoulder-button zoom. Fixed the initial integration to explicitly open a
controller on `SDL_EVENT_GAMEPAD_ADDED`; initializing the subsystem alone only
discovers devices and does not enable axis/button events.

Also repaired the landscape touch-controls editor: actions now live in a
horizontally scrollable row, the edit dialog scrolls on short displays, new
buttons spawn fully on-screen, and the command-panel placement guide is
labelled.

Built Android version 120 with the existing `build-android.yml` workflow,
installed it over the previous build, and smoke-tested startup through the
animated main menu. The clean launch log contained no allocation failure,
SIGSEGV, SIGABRT, or Android fatal exception. Added `AI_CONTEXT.md` as a compact
handoff for future coding agents and refreshed the README for the v120 release.

Fixed Android task navigation in the SDL Java patch. The system-UI visibility
callback used to hide the navigation bar again immediately after the player
revealed it, leaving no time to complete Home or recents. Fullscreen is still
requested on game entry, but a deliberate system-navigation gesture is no
longer overridden by the app.

Finished the controller UX instead of leaving it as an invisible mouse. The
right stick now drives a software-rendered copy of the current Generals cursor,
including the game's context-sensitive cursor changes. Added a Setup editor for
cursor/camera speed, stick deadzone, cursor visibility, and seven configurable
hotkeys. The defaults use E/Q/Space and control groups 1-4, while clicks, menu,
and zoom remain on predictable fixed buttons. Both the game and control editors
now accept either landscape rotation for phones with a USB-C cable or controller
plug on one side.
